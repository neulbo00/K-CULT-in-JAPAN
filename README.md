# K-CULT-in-JAPAN

일본에서 열리는 한류 이벤트를 기간별 통계와 전체 일정 아카이브로 살펴보는 데이터 대시보드입니다.

- **공개 사이트**: https://neulbo00.github.io/K-CULT-in-JAPAN/
- **데이터 원본**: Notion 「일본 한류 이벤트」 마스터 DB
- **배포 구조**: GitHub Pages 정적 사이트
- **데이터 갱신**: Windows 로컬 환경의 `.env`에 저장된 Notion API 토큰 사용 (토큰 파일은 저장소에 커밋하지 않음)
- **Cloudflare Worker**: 사용하지 않음

## 현재 기능

- 통계 기본값은 현재 연도(2026년)
- 연도 선택, 전체 기간, 직접 날짜 범위 설정
- 기간에 맞춘 스냅샷·월별 추이·유형·카테고리·프로모터 재집계
- 유형 및 카테고리별 건수·비율 표시
- 그래프 항목을 눌러 관련 이벤트 목록으로 이동
- 과거·진행 중·예정 이벤트 구분 및 검색
- 이벤트명·아티스트·프로모터 검색
- 공식 출처 링크 표시

## 데이터 범위와 집계 기준

2026-11-27 Notion 마스터 DB의 활성 레코드 311건을 공개용 필드로 추출했습니다.

| 공연 시작 연도 | 이벤트 수 |
|---|---:|
| 2025 | 7 |
| 2026 | 283 |
| 2027 | 20 |
| 시작일 미등록 | 1 |
| 전체 | 311 |

- 통계 기간은 **공연 시작일** 기준으로 적용합니다.
- 날짜가 없는 1건은 연도별 통계와 일정 검색에서 제외하며 전체 DB 건수에는 포함합니다.
- 카테고리가 비어 있는 레코드는 **미분류**로 표시합니다.
- 이벤트 상태는 오늘 날짜와 공연 시작일·종료일을 기준으로 예정·진행 중·종료로 구분합니다.
- 메인 이벤트 아카이브는 이벤트 마스터 DB 311건을 사용합니다. 지도는 별도 공연 일정 DB의 공개 대상 회차별 레코드를 사용합니다.
- 지역별 데이터는 원본에 확인 가능한 지역 필드가 별도 연결되기 전까지 수치화하지 않습니다.

## 보안 및 배포

- Notion API 토큰은 로컬 Windows 프로젝트의 `.env`에만 보관합니다.
- `.env`, 토큰, 인증정보는 GitHub에 올리지 않습니다.
- Cloudflare Worker는 사용하지 않습니다.
- GitHub Pages는 정적 파일만 제공합니다. Notion API 토큰을 브라우저에 노출하지 않습니다.

## Windows 자동 동기화 (매일 06:00)

자동화 파일:
- `sync_notion.py`: Notion 이벤트 마스터와 공연 일정 DB를 각각 페이지네이션 조회하고, `data.js`와 `schedule_data.js`를 함께 갱신
- `sync.bat`: 수동/예약 실행 및 logs/sync.log 기록
- `install_task.ps1`: 현재 Windows 사용자로 매일 오전 06:00 작업 스케줄러 등록
- `.gitignore`: .env와 로그 파일을 Git에서 제외

최초 설정:
1. 이 저장소를 Windows PC의 기존 프로젝트 폴더에 최신 상태로 가져옵니다.
2. 기존 로컬 `.env`에 이미 쓰고 있는 Notion 토큰 변수명을 유지합니다. 스크립트는 `NOTION_API_KEY`, `NOTION_TOKEN`, `NOTION_API_TOKEN`을 인식합니다.
3. Git for Windows와 Git Credential Manager가 설정되어 있어야 합니다. 스크립트는 토큰을 저장하지 않고 기존 Git 인증을 사용해 `git push origin main`을 수행합니다.
4. Python 3가 설치되어 있어야 합니다. 외부 Python 패키지는 필요하지 않습니다.
5. PowerShell에서 프로젝트 폴더로 이동한 뒤 다음을 실행합니다:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\install_task.ps1`
6. 먼저 `sync.bat`를 직접 실행하고 `logs\sync.log`에서 성공 여부를 확인합니다.

안전장치:
- 활성 이벤트가 기본 최소 기준 250건보다 적으면 공개 데이터를 덮어쓰지 않습니다. 기준은 로컬 .env의 `SYNC_MIN_RECORDS`로 조정할 수 있습니다.
- 공개 공연 일정이 기본 최소 기준 100건보다 적으면 일정 데이터를 덮어쓰지 않습니다. 기준은 로컬 .env의 `SYNC_MIN_SCHEDULES`로 조정할 수 있습니다.
- 데이터가 바뀌지 않으면 Git 커밋과 푸시를 생략합니다.
- 현재 브랜치가 main이 아니면 자동 푸시를 중단합니다.
- Notion 토큰은 로컬 .env에서만 읽으며 브라우저와 GitHub에 전송하지 않습니다.
- PC가 꺼져 있거나 절전 상태라면 예약 시각에 실행되지 않을 수 있습니다. 작업 스케줄러의 놓친 작업 시작 옵션이 활성화되어 있습니다.
- GitHub Pages는 main 변경 후 자동 배포됩니다.

## 일본 지역별 한류 분포 (04 / Japan Map)

- 지도 데이터 원본은 Notion 별도 DB **「일본 한류 공연 일정」**입니다. 이벤트 마스터 DB와 Relation으로 연결된 개별 회차 레코드를 사용합니다.
- `sync_notion.py`가 이벤트 마스터와 공연 일정 DB를 함께 조회해 `data.js`와 `schedule_data.js`를 생성합니다. 기존 Windows 작업 스케줄러의 `sync.bat` 실행 흐름을 유지하며 Cloudflare Worker는 사용하지 않습니다.
- `schedule_data.js`에는 Notion의 `노출대상=true` 공개 뷰에 포함된 일정만 내보냅니다. 2026-11-27 조사 기준 공개 일정 578건, 고유 공연장 표기 164개이며, 공연일 범위는 2026-11-28~2027-05-16입니다.
- 8개 권역별 공개 일정: 関東 377건, 関西 114건, 九州・沖縄 29건, 中部 32건, 北海道 6건, 東北 6건, 四国 8건, 中国 5건. 권역 미입력 1건은 지도 집계에서 제외합니다.
- 집계 단위는 고유 이벤트가 아니라 **개별 공연 일정 레코드**입니다. 동일 이벤트의 다회차는 각각 한 건으로 계산합니다.
- 현재 공개 뷰의 578건은 모두 공연 상태가 예정으로 등록되어 있습니다. 기존 기간 필터는 이벤트 시작일이 아니라 **개별 공연일**에 적용합니다.
- 지도는 일본 47개 도도부현 경계를 위치 참고용으로 사용하지만, 색상과 수치는 Notion의 8개 권역 합계입니다. 같은 권역에 속한 도도부현은 동일한 색으로 표시하며, 이를 도도부현별 개별 건수로 해석하지 않습니다.
- 공연장 표기 164개가 곧 164개 주소 검증을 뜻하지는 않습니다. 개별 도도부현별 통계는 공연장 주소를 별도로 검증한 이후에만 추가합니다.
- 지도 경계 데이터: 국토교통성 국土数値情報 「行政区域データ 2025年版」을 가공한 GeoJSON 47개 도도부현 경계. 원 데이터는 CC BY 4.0이며, 출처 표기를 유지합니다.
- 경계 데이터 출처: [国土数値情報 行政区域データ 2025年版](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html), 가공본 제공: [kyodo-official/japan-choropleth](https://github.com/kyodo-official/japan-choropleth)
- 지도 렌더링: Leaflet 1.9.4 (CDN), 외부 배경 타일 없이 저장소의 GeoJSON 경계만 표시합니다.
